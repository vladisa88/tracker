# 01: Вход владельца и запуск приложения

**What to build:** Владелец запускает приложение локально, входит через Telegram и видит защищённый адаптивный экран приложения; посторонние не получают доступ. Создать работающий фундамент React + Vite на JavaScript, Go API и PostgreSQL с сохранением сессий. Источник требований — согласованная спецификация первой версии; соблюдать словарь и ADR.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**User stories:** 1, 2, 3, 4, 31, 33.

- [x] Инициализирован Git, если репозитория ещё нет; существующие документы и настройки сохранены. Работу можно проверять ревью и фиксировать коммитами.
- [x] Docker Compose запускает приложение и настоящую PostgreSQL; фронтенд и API доступны через один origin. Миграции создают исходную схему, данные сохраняются при перезапуске.
- [x] Telegram Login использует OIDC Authorization Code Flow с PKCE. Сервер проверяет подпись, срок действия, обязательные утверждения и связь ответа с конкретным запросом входа.
- [x] Разрешён только числовой Telegram ID владельца из конфигурации. Чужой аккаунт, подмена ID фронтендом и неверный или истёкший результат входа не создают сессию.
- [x] Реализованы начало/завершение входа, получение сессии и выход согласно контракту API. После выхода или истечения сессии закрытые запросы отвергаются; будущие маршруты могут использовать тот же механизм защиты.
- [x] Cookie-сессия защищена HttpOnly, сроком действия, подходящим SameSite и Secure при HTTPS; изменяющие запросы защищаются от CSRF.
- [x] Русский экран входа и оболочка приложения удобны на телефоне и компьютере: молочный фон, графитовый текст, зелёные акценты, понятные ошибки и управление с клавиатуры. Пока подписки не реализованы, оболочка не изображает работающие действия или выдуманную аналитику.
- [x] Секреты задаются серверной конфигурацией и не попадают в сборку фронтенда, ответы или журналы. Ошибки конфигурации выявляются при запуске. Проверки живости и готовности отражают состояние процесса, базы и схемы без раскрытия внутренних данных.
- [x] Подготовлен воспроизводимый запуск проверок через API с настоящей тестовой PostgreSQL и управляемыми Telegram Login/временем; тестовая подмена авторизации недоступна в production. Браузерная проверка подтверждает вход, отказ чужому аккаунту и выход.
- [x] Записаны команды запуска и проверки, результаты тестирования и состояние завершения задачи. Реальный домен и секреты Telegram не требуются для автоматических тестов; их живая проверка относится к развёртыванию.

## Implementation

**Состояние реализации: завершена.** Все критерии приёмки проверены 16 октября 2026 года. Статус `ready-for-agent` выше обозначает triage, завершение фиксируется отдельно.

Реализованы React/Vite на JavaScript, Go API с общей защитой закрытых маршрутов, PostgreSQL-миграция под advisory lock, OIDC Code Flow с PKCE S256 и RS256/JWKS, проверка числового Telegram `id` (отдельно от `sub`), nonce/state и одноразового контекста браузера, сохраняемые семидневные сессии и CSRF. Подмена Telegram и времени включена только через внешние зависимости; браузерный провайдер существует исключительно в Go test binary.

Существующие документы сохранены исходным коммитом `cdc62f1`. Первоначальная реализация: `04de7bd`, исправления после ревью: `fe73d05`. После предоставления доступа история перенесена из временного `.git-storage` в обычный `.git` на ветке `main`; стандартные команды Git работают. Коммит `6e13078` фиксирует npm lockfile, переход на `npm ci` и обновление Vite до 7.3.7 с устранением найденных npm audit уязвимостей.

## Validation

Команды запуска и проверки: [README](../../../README.md). Финальный `./scripts/check.sh` завершился успешно без живых секретов Telegram:

- Чистая настоящая PostgreSQL 17 запущена через тестовый Compose; миграция применена автоматически.
- `npm ci --ignore-scripts`, `npm run typecheck` на TypeScript 5.9.3 и `npm run build` на Vite 7.3.7 проходят.
- `go vet ./...` и `go test -race ./... -count=1` проходят на Go 1.20.2 с настоящей PostgreSQL. Проверены вход владельца, чужой ID, неверная подпись, issuer/audience/nonce, обязательные claims, просроченный и повторный callback, PKCE, подмена ID фронтендом, CSRF, сохранение сессии при новом экземпляре приложения/подключении, отзыв сессии при выходе и истечение срока. Тест браузерного сервера запускается отдельно через Playwright.
- Playwright: **4 passed** — вход/перезагрузка/выход и отказ чужому аккаунту на desktop и phone (Chromium). Проверено отсутствие горизонтального переполнения защищённого экрана.
- `npm audit`: **0 vulnerabilities**.
- `docker build -t tracking:owner-login .` проходит; рабочий Compose также собрал образ с Node 24 и Go 1.26.
- В отдельном проекте Compose с фиктивной конфигурацией проверены чистый запуск, готовность, русский HTML и JavaScript с того же origin, отказ анонимному запросу и начало OIDC-входа. При остановленной базе readiness возвращает 503, liveness — 200.
- После полного `docker compose down` и повторного `up -d --wait` без удаления volume сохранённый до остановки контекст входа принимается callback, а его повтор отклоняется. Это проверено через HTTP, без чтения внутренних таблиц. Миграция повторно проходит без потери схемы и данных.
- Тестовые контейнеры, сети и volume удалены после проверки; рабочая база не использовалась.
- `git diff --check` проходит. Независимое двухосевое ревью и повторное ревью `fe73d05...6e13078` выполнены; [отчёт](../../../docs/reviews/01-owner-login.md). Все замечания исправлены.

Живая проверка Telegram с реальным доменом и секретами остаётся частью развёртывания (задача 09), как предусмотрено этим тикетом.
