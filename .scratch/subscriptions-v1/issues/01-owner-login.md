# 01: Вход владельца и запуск приложения

**What to build:** Владелец запускает приложение локально, входит через Telegram и видит защищённый адаптивный экран приложения; посторонние не получают доступ. Создать работающий фундамент React + Vite на JavaScript, Go API и PostgreSQL с сохранением сессий. Источник требований — согласованная спецификация первой версии; соблюдать словарь и ADR.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**User stories:** 1, 2, 3, 4, 31, 33.

- [x] Инициализирован Git, если репозитория ещё нет; существующие документы и настройки сохранены. Работу можно проверять ревью и фиксировать коммитами.
- [ ] Docker Compose запускает приложение и настоящую PostgreSQL; фронтенд и API доступны через один origin. Миграции создают исходную схему, данные сохраняются при перезапуске.
- [x] Telegram Login использует OIDC Authorization Code Flow с PKCE. Сервер проверяет подпись, срок действия, обязательные утверждения и связь ответа с конкретным запросом входа.
- [x] Разрешён только числовой Telegram ID владельца из конфигурации. Чужой аккаунт, подмена ID фронтендом и неверный или истёкший результат входа не создают сессию.
- [x] Реализованы начало/завершение входа, получение сессии и выход согласно контракту API. После выхода или истечения сессии закрытые запросы отвергаются; будущие маршруты могут использовать тот же механизм защиты.
- [x] Cookie-сессия защищена HttpOnly, сроком действия, подходящим SameSite и Secure при HTTPS; изменяющие запросы защищаются от CSRF.
- [x] Русский экран входа и оболочка приложения удобны на телефоне и компьютере: молочный фон, графитовый текст, зелёные акценты, понятные ошибки и управление с клавиатуры. Пока подписки не реализованы, оболочка не изображает работающие действия или выдуманную аналитику.
- [x] Секреты задаются серверной конфигурацией и не попадают в сборку фронтенда, ответы или журналы. Ошибки конфигурации выявляются при запуске. Проверки живости и готовности отражают состояние процесса, базы и схемы без раскрытия внутренних данных.
- [ ] Подготовлен воспроизводимый запуск проверок через API с настоящей тестовой PostgreSQL и управляемыми Telegram Login/временем; тестовая подмена авторизации недоступна в production. Браузерная проверка подтверждает вход, отказ чужому аккаунту и выход.
- [x] Записаны команды запуска и проверки, результаты тестирования и состояние завершения задачи. Реальный домен и секреты Telegram не требуются для автоматических тестов; их живая проверка относится к развёртыванию.

## Implementation

Реализация подготовлена; задача **не завершена по приёмке** до успешного запуска Compose и интеграционных/браузерных проверок. Статус triage сохранён отдельно от состояния реализации. Не отмеченные критерии требуют исполнения в доступной среде, а не только наличия исходного кода.

Git создан с метаданными в `.git-storage`: среда запрещает запись в `.git`. Существующие документы сохранены отдельным исходным коммитом `cdc62f1`. Для команд используется `GIT_DIR=.git-storage GIT_WORK_TREE=.`; перенос в обычный `.git` описан в README.

Реализованы React/Vite на JavaScript, Go API с общей защитой закрытых маршрутов, PostgreSQL-миграция под advisory lock, OIDC Code Flow с PKCE S256 и RS256/JWKS, проверка числового Telegram `id` (отдельно от `sub`), nonce/state и одноразового контекста браузера, сохраняемые семидневные сессии и CSRF. Подмена Telegram и времени включена только через внешние зависимости; браузерный провайдер существует исключительно в Go test binary.

## Validation

- Команды запуска и полного прогона: [README](../../../README.md), `./scripts/check.sh`.
- `go vet ./...` проходит на Go 1.20.2 с кешированными зависимостями.
- Финальный `go test -race ./... -count=1 -v` проходит: HTTP-проверка неавторизованного доступа выполнена, гонок не обнаружено; интеграционные тесты явно пропускаются без `TEST_DATABASE_URL`.
- JavaScript `checkJs` проходит с доступными в кеше TypeScript 4.9.4 и типами React 18, через временный compiler configuration с Node resolution. Это вспомогательная проверка исходников; зафиксированный npm toolchain TypeScript 5.9.3/Vite 7.3.1 не установлен и не проверен.
- `docker compose config --quiet` для рабочего Compose (с фиктивной конфигурацией) и тестового Compose проходит. `sh -n scripts/check.sh` и `git diff --check` проходят.
- PostgreSQL integration, сборка образа, сохранность при настоящем перезапуске, браузерные desktop/phone сценарии **не выполнялись**: Docker daemon недоступен. Загрузка npm/Go из shell недоступна; `npm install --offline` завершается ENOTCACHED для Playwright. Lockfile npm не создан; его нужно получить и зафиксировать при доступной установке зависимостей.
- Независимое двухосевое ревью выполнено. Замечания по записи результатов в тикет и проверке STATIC_DIR исправлены; [отчёт](../../../docs/reviews/01-owner-login.md).

Следующий шаг при доступном окружении: выполнить `./scripts/check.sh`, исправить выявленные проблемы, зафиксировать npm lockfile и только после успешного результата закрыть два оставшихся критерия. Живая проверка Telegram остаётся частью развёртывания.
