# 02: Добавление подписок и список ближайших платежей

**What to build:** Владелец добавляет регулярный расход и видит сохранённую подписку с суммой, валютой и актуальной следующей датой платежа после перезагрузки. Основной экран становится рабочим списком на телефоне и компьютере. Следовать согласованной спецификации первой версии, словарю и ADR о плановых платежах и фиксированных днях.

**Blocked by:** 01 — Вход владельца и запуск приложения.

**Status:** ready-for-agent

**User stories:** 4, 5, 6, 7, 8, 9, 10, 13, 14, 31, 32.

- [x] Подписка имеет стабильный ID, название, точную положительную сумму, валюту, период, следующую дату, признак архива и время создания/изменения. Миграция применяется к базе, созданной задачей 01.
- [x] Создание, список активных/архивных записей и метаданные работают по согласованному HTTP API; доступны только владельцу, включая защиту изменяющих запросов. Формат ошибок и HTTP-коды соответствуют спецификации.
- [x] Метаданные содержат периоды 30/90/180/365 дней, поддерживаемые валюты с дробной точностью и Europe/Moscow. Минимум поддерживаются RUB, USD и EUR. Суммы передаются десятичными строками и сохраняются без двоичного floating point.
- [x] Пустое название, неположительная или неверная сумма, недопустимая валюта/точность, неизвестный период и дата в прошлом отвергаются без частичных записей.
- [x] Для просроченной активной подписки дата переносится на минимальное целое число периодов до сегодня или будущего дня; сегодняшняя дата остаётся до окончания дня по Москве. Нет подтверждения «Оплачено» или утверждения о фактическом списании.
- [x] Расписание рассчитывается в одном модуле приложения и доступно будущим итогам и напоминаниям. Прогноз корректен после долгого простоя, без предварительного открытия сайта; архивные даты не нормализуются.
- [x] Активные подписки сортируются по следующей дате, затем названию и ID. На телефоне отображаются карточки, на компьютере — компактный список с суммой, валютой, периодом и датой.
- [x] Есть пустое состояние, заметное добавление, состояния загрузки и ошибки. Форма сохраняет ввод при исправимой ошибке, блокирует повторную отправку до ответа и показывает успех только после сохранения сервером.
- [x] Проверки API с PostgreSQL подтверждают сохранение после повторного подключения, валидацию, порядок списка и независимость расчёта от часового пояса сервера. Управляемое время покрывает сегодня, вчера, долгий простой, конец месяца, год и високосный день.
- [x] Браузерная проверка подтверждает добавление и сохранность результата после перезагрузки на мобильном и широком экранах; поля доступны с клавиатуры и имеют текстовые ошибки. Записаны результаты проверок и завершение задачи.


## Implementation

**Состояние реализации: завершена.** Критерии приёмки проверены 16 октября 2026 года; `ready-for-agent` обозначает triage, завершение записано отдельно.

Реализованы миграция 2 поверх схемы входа, точные суммы PostgreSQL numeric и десятичные строки JSON, защищённые метаданные/создание/активный и архивный списки. Валидация возвращает ошибки полей без частичных записей. Общий модуль `internal/subscriptions` рассчитывает фиксированные периоды по бизнес-дате Москвы; `ListSubscriptions` доступен будущим итогам и фоновым напоминаниям. Чтение вычисляет текущую дату из исходного графика без изменения архивных записей и времён создания/редактирования.

Интерфейс: русская форма с сохранением ввода и блокировкой отправки до ответа, серверное подтверждение успеха, активный список/архив, пустые состояния, ошибки загрузки и повторная попытка. На телефоне — карточки, на компьютере — компактный список. Редактирование, действия архивации, итоги и напоминания остаются в последующих задачах.
