# 03: Редактирование, архив и восстановление

**What to build:** Владелец меняет цену и график подписки, прекращает учёт архивированием и возобновляет его восстановлением с новой датой. Все действия проходят через настоящий интерфейс, API и сохранение в PostgreSQL согласно спецификации первой версии.

**Blocked by:** 02 — Добавление подписок и список ближайших платежей.

**Status:** ready-for-agent

**User stories:** 7, 11, 12, 15, 16, 17, 31, 32.

- [ ] Реализованы изменение полей, архивирование и восстановление по контракту API; проверяются сессия владельца и CSRF. Неизвестный ID возвращает 404, недопустимые поля — 422, конфликт состояния — 409.
- [ ] Название, сумма, валюта, период и дата сохраняются атомарно. При неверном вводе прежние данные не меняются, а форма сохраняет ввод и показывает ошибки.
- [ ] Изменение названия, суммы или периода само по себе не сдвигает актуальную следующую дату. Новый период отсчитывается от этой даты. Явно указанная дата должна быть сегодня или позже по Москве.
- [ ] Архивирование убирает подписку из активного списка, сохраняя запись в отдельном архиве. Повторная архивация не создаёт побочных действий. Физическое удаление не добавляется.
- [ ] Восстановление требует заново указать следующую дату сегодня или в будущем; восстановление активной записи возвращает конфликт. Успех возвращает запись в список с правильным порядком.
- [ ] Состояние архива используется общими выборками приложения, чтобы архивная подписка не участвовала в прогнозе и напоминаниях; срок доступа к сервису не учитывается.
- [ ] Русские формы редактирования и восстановления, архив и действия доступны на телефоне, компьютере и с клавиатуры. Переходы имеют аккуратные анимации с учётом reduced motion.
- [ ] Проверки API с PostgreSQL подтверждают изменение, атомарность ошибок, архив, повторную архивацию и восстановление. Браузерный сценарий проходит весь цикл с проверкой результата после перезагрузки. Записаны результаты и завершение задачи.
