# 03: Редактирование, архив и восстановление

**What to build:** Владелец меняет цену и график подписки, прекращает учёт архивированием и возобновляет его восстановлением с новой датой. Все действия проходят через настоящий интерфейс, API и сохранение в PostgreSQL согласно спецификации первой версии.

**Blocked by:** 02 — Добавление подписок и список ближайших платежей.

**Status:** ready-for-agent

**User stories:** 7, 11, 12, 15, 16, 17, 31, 32.

- [x] Реализованы изменение полей, архивирование и восстановление по контракту API; проверяются сессия владельца и CSRF. Неизвестный ID возвращает 404, недопустимые поля — 422, конфликт состояния — 409.
- [x] Название, сумма, валюта, период и дата сохраняются атомарно. При неверном вводе прежние данные не меняются, а форма сохраняет ввод и показывает ошибки.
- [x] Изменение названия, суммы или периода само по себе не сдвигает актуальную следующую дату. Новый период отсчитывается от этой даты. Явно указанная дата должна быть сегодня или позже по Москве.
- [x] Архивирование убирает подписку из активного списка, сохраняя запись в отдельном архиве. Повторная архивация не создаёт побочных действий. Физическое удаление не добавляется.
- [x] Восстановление требует заново указать следующую дату сегодня или в будущем; восстановление активной записи возвращает конфликт. Успех возвращает запись в список с правильным порядком.
- [x] Состояние архива используется общими выборками приложения, чтобы архивная подписка не участвовала в прогнозе и напоминаниях; срок доступа к сервису не учитывается.
- [x] Русские формы редактирования и восстановления, архив и действия доступны на телефоне, компьютере и с клавиатуры. Переходы имеют аккуратные анимации с учётом reduced motion.
- [x] Проверки API с PostgreSQL подтверждают изменение, атомарность ошибок, архив, повторную архивацию и восстановление. Браузерный сценарий проходит весь цикл с проверкой результата после перезагрузки. Записаны результаты и завершение задачи.


## Implementation

**Состояние реализации: завершена.** 16 октября 2026 года; triage `ready-for-agent` сохранён отдельно от завершения.

Реализованы PATCH разрешённых полей, идемпотентная архивация и восстановление с новой обязательной датой. Изменения выполняются в транзакции с блокировкой записи: сначала актуализируется дата по старому периоду, затем применяются новые поля. Неверные поля, типы и даты не изменяют запись. Архивный статус меняется только отдельными операциями; повторная архивация сохраняет время изменения и дату. Общая выборка `ListSubscriptions` исключает архив из активного набора для будущих итогов и напоминаний.

Русские формы редактирования и восстановления используют сохранение ввода, ошибки полей, блокировку повторной отправки и подтверждение сервера. Неизменённая дата при редактировании не отправляется: сервер сохраняет актуальную дату даже при переходе полуночи. Восстановление начинается с пустого поля новой даты. Действия доступны с клавиатуры на телефоне и компьютере; анимации учитывают reduced motion.
