# 04: Прогноз расходов по валютам

**What to build:** Владелец видит над списком два разных показателя: платежи в ближайшие 30 дней и среднюю нагрузку за 30 дней, отдельно по каждой валюте. Расчёт выполняет Go API по сохранённым подпискам; React показывает его результат согласно спецификации.

**Blocked by:** 02 — Добавление подписок и список ближайших платежей.

**Status:** ready-for-agent

**User stories:** 18, 19, 20, 31, 32.

- [x] Закрытый endpoint итогов возвращает текущую бизнес-дату по Москве, границы окна и оба показателя по исходным валютам. Денежные значения передаются десятичными строками.
- [x] Окно ближайших платежей включает сегодня и день +29, исключает день +30. Суммируются попавшие в окно плановые события; просроченные даты нормализуются общим правилом расписания.
- [x] Средняя нагрузка равна сумме стоимости каждой активной подписки × 30 ÷ период в днях и не зависит от попадания следующей даты в окно. Годовой период составляет 365 дней.
- [x] Используется точная арифметика. Округление до точности валюты выполняется после суммирования; ровная половина округляется от нуля.
- [x] Архивные записи исключены из обоих итогов, валюты не смешиваются, курс не применяется, пустые данные не создают фиктивных расходов.
- [x] Показатели имеют явные русские подписи, крупные суммы и состояния загрузки/ошибки; удобны на телефоне и компьютере. После доступных операций над подписками итоги обновляются без полной перезагрузки.
- [x] Проверки API с настоящей PostgreSQL и управляемым временем покрывают границы окна, несколько валют, архив, пустой список, дробные суммы и деление годовой стоимости. Архивные данные можно подготовить фикстурами: наличие интерфейса архивирования не блокирует эту задачу.
- [x] Браузерный сценарий подтверждает обновление итогов после добавления и различие двух показателей. Записаны результаты проверок и завершение задачи.


## Implementation

**Состояние реализации: завершена.** Проверено 16 октября 2026 года; `ready-for-agent` остаётся triage-статусом, завершение записано отдельно.

Закрытый `GET /api/summary` возвращает `today`, `windowStart`, `windowEndExclusive` и массив `currencies`. Каждая запись содержит `currency`, `upcoming` и `average`; суммы — десятичные строки с точностью валюты. Конец окна исключён. Пустой набор активных подписок возвращает пустой массив, валюта активной подписки вне окна имеет нулевые ближайшие платежи и рассчитанную среднюю нагрузку.

API читает активные подписки через общий `ListSubscriptions` с единым снимком времени, нормализует расписание без предварительного чтения списка и считает события в окне. Средняя нагрузка использует точные рациональные значения `amount × 30 / periodDays`; `math/big.Rat` сохраняет дроби до суммирования и округляет ровную половину от нуля только при выдаче итога валюты. Архив исключён, конвертация отсутствует.

Над списком расположены два русских показателя, границы окна и московская бизнес-дата. Крупные суммы адаптируются к телефону и компьютеру. Есть отдельные загрузка, ошибка и повторная попытка; ошибка итогов не блокирует список и форму. Добавление, редактирование, архивирование, восстановление и возврат на вкладку обновляют итоги без перезагрузки. В браузерной фикстуре зафиксировано время, сценарии одного владельца выполняются последовательно, чтобы параллельные изменения общей базы не влияли на проверки итогов.

## Validation

- Полный `./scripts/check.sh` прошёл: JavaScript `checkJs`, Vite build, `go vet ./...`, `go test -race ./... -count=1` с настоящей PostgreSQL 17 и **14 браузерных проверок** Chromium (12 основного интерфейса, 2 подключения Telegram), на телефоне и компьютере. `npm ci`: 0 vulnerabilities.
- HTTP API: недоступность без сессии, пустой набор, окно от сегодня до +30 исключительно (включая +29), отдельные RUB/USD/EUR, исключение архива, годовой период 365 дней, дробные и очень большие точные суммы. Три шестых доли копейки дают половину копейки и округляются после суммирования в `0.01`; деление годовой стоимости проверяется вместе с другими дробями.
- Управляемые часы: московская дата при ещё предыдущей дате UTC, високосный день и нормализация после четырёх лет без чтения списка. Отдельный запуск `TestSummary` с `TZ=Pacific/Honolulu` прошёл.
- Браузер: добавление годовой подписки на 365 увеличивает ближайшие платежи на 365, среднюю нагрузку на 30; редактирование, архивирование и восстановление с датой вне окна обновляют оба показателя. Проверены загрузка, ошибка сервера, повтор с настоящим API, доступность формы при ошибке итогов и отсутствие горизонтального переполнения.
- TDD: первый HTTP-тест зафиксировал отсутствие `/api/summary` (404); первый браузерный сценарий зафиксировал отсутствие показателей. После реализации соответствующие проверки прошли.
