# 04: Прогноз расходов по валютам

**What to build:** Владелец видит над списком два разных показателя: платежи в ближайшие 30 дней и среднюю нагрузку за 30 дней, отдельно по каждой валюте. Расчёт выполняет Go API по сохранённым подпискам; React показывает его результат согласно спецификации.

**Blocked by:** 02 — Добавление подписок и список ближайших платежей.

**Status:** ready-for-agent

**User stories:** 18, 19, 20, 31, 32.

- [ ] Закрытый endpoint итогов возвращает текущую бизнес-дату по Москве, границы окна и оба показателя по исходным валютам. Денежные значения передаются десятичными строками.
- [ ] Окно ближайших платежей включает сегодня и день +29, исключает день +30. Суммируются попавшие в окно плановые события; просроченные даты нормализуются общим правилом расписания.
- [ ] Средняя нагрузка равна сумме стоимости каждой активной подписки × 30 ÷ период в днях и не зависит от попадания следующей даты в окно. Годовой период составляет 365 дней.
- [ ] Используется точная арифметика. Округление до точности валюты выполняется после суммирования; ровная половина округляется от нуля.
- [ ] Архивные записи исключены из обоих итогов, валюты не смешиваются, курс не применяется, пустые данные не создают фиктивных расходов.
- [ ] Показатели имеют явные русские подписи, крупные суммы и состояния загрузки/ошибки; удобны на телефоне и компьютере. После доступных операций над подписками итоги обновляются без полной перезагрузки.
- [ ] Проверки API с настоящей PostgreSQL и управляемым временем покрывают границы окна, несколько валют, архив, пустой список, дробные суммы и деление годовой стоимости. Архивные данные можно подготовить фикстурами: наличие интерфейса архивирования не блокирует эту задачу.
- [ ] Браузерный сценарий подтверждает обновление итогов после добавления и различие двух показателей. Записаны результаты проверок и завершение задачи.
