# 06: Ежедневная подборка платежей

**What to build:** Подключённый владелец получает одну ежедневную подборку о плановых платежах сегодня и через три дня; пустые дни не создают сообщения. Реализовать основной путь от сохранённых подписок до сообщения, включая постоянный журнал доставки, по спецификации первой версии.

**Blocked by:** 02 — Добавление подписок и список ближайших платежей; 05 — Подключение Telegram-бота.

**Status:** ready-for-agent

**User stories:** 23, 24, 25, 28, 30.

- [x] Цикл фоновой обработки использует управляемое время и Europe/Moscow. Первая проверка не раньше 10:00 формирует подборку текущего дня; дата сервера и предварительное открытие сайта на расчёт не влияют.
- [x] Применяется общий прогноз дат. Включаются только активные подписки с датой сегодня или через три дня; архивные, завтрашние и более дальние платежи не попадают в сообщение.
- [x] Разделы «Сегодня» и «Через 3 дня» содержат название, сумму, валюту и дату; пустой раздел опускается. Названия безопасно отображаются в выбранном формате сообщения.
- [x] Сообщение содержит ссылку на приложение с обычной авторизацией без секретов и финансовых данных в URL. Большая подборка сокращается до одного допустимого сообщения с количеством платежей и ссылкой на полный список.
- [x] Одна постоянная запись на дату фиксирует содержимое до первой попытки, пустой результат и подтверждённый успех. Повторный обычный цикл или перезапуск не повторяет успешную отправку и не пересчитывает уже обработанный пустой день.
- [x] Если бот не подключён, сообщения неизвестному получателю не отправляются; приложение остаётся пригодным для учёта.
- [x] Изменения после обработанной подборки видны на сайте сразу, но не создают дополнительного сообщения в тот же день. Проверочное сообщение подключения является отдельным действием.
- [x] Есть проверяемый запуск одного цикла обработки с заданным временем, настоящей PostgreSQL и подменным Telegram. Проверены до/после 10:00, нужные даты, архив, пустой день, формат/размер, изменения после отправки и обычный перезапуск.
- [x] Не обещается строго однократная доставка. Расширенные сценарии сбоев и параллельного исполнения явно оставлены задаче 07; отсутствие этой задачи не выдаётся за полную готовность production-доставки. Записаны результаты проверок и завершение задачи.


## Implementation

**Состояние реализации: завершена.** Проверено 16 октября 2026 года. `ready-for-agent` остаётся triage-меткой; завершение учтено отдельно. Зависимости 02 и 05 завершены до начала работы.

Реализован публичный `DigestWorker.Cycle(ctx, now)` и отдельный процесс `/digest`, запускаемый сервисом `digest` в Docker Compose. Проверка при старте и раз в минуту использует Europe/Moscow и не отправляет до 10:00. Общая операция чтения подписок переиспользует прогноз фиксированных периодов, независимо от посещения сайта. Сообщение содержит только активные платежи сегодня и через три дня, точные суммы и валюты, даты и обычную ссылку на приложение. Plain text сохраняет HTML/Markdown в названиях буквально. Большой текст заменяется одной компактной подборкой с количеством платежей и ссылкой; ограничение считается консервативно в UTF-16.

Миграция 3 добавляет постоянный `daily_digests` с уникальной бизнес-датой, получателем, содержимым, состояниями pending/empty/sent и временем создания/подтверждённой отправки. Снимок сохраняется до первой внешней попытки. Пустой день и подтверждённый успех переживают перезапуск и не пересчитываются после изменений подписок. Пока бот не подключён, отправки и фиксации дня нет; подключение до конца дня позволяет сформировать подборку. Проверочное сообщение `/start` остаётся отдельным действием.

Настройка, журнал и ограничения: [docs/daily-digest.md](../../../docs/daily-digest.md). Основная реализация: `74283a7`. Независимое двухосевое [ревью](../../../docs/reviews/06-daily-payment-digest.md): Standards — 0 оставшихся замечаний, Spec — 0. Замечание по отсутствию итоговой записи закрыто этим разделом.

## Validation

- TDD: первый тест основного пути до реализации завершался ошибкой сборки `undefined: app.NewDigestWorker`; после реализации прошёл с настоящей PostgreSQL 17.
- Целевой прогон `TEST_DATABASE_URL=... go test ./internal/app -run '^TestDigest' -race -count=1`: **5 тестов проходят**. У каждого сценария отдельная схема PostgreSQL; данные создаются и изменяются через защищённый HTTP API, внешний Telegram подменяется на уровне HTTP transport. Между циклами открываются новые подключения к базе и создаётся новый worker.
- Проверены 09:59:59 и 10:00 по Москве, опоздание в тот же день, следующий московский день и запрет до 10:00, нормализация графика после месяца без чтения сайта, активные сегодня/+3, исключение завтра/+4/архива. Время запуска с offset -10:00 имеет другую календарную дату, чем Москва; результат остаётся московским. Сценарий также задаёт `TZ=Pacific/Honolulu`.
- Проверены буквальные HTML/Markdown и emoji в названии, точная большая дробная сумма, отсутствие пустого раздела, сокращение 22 платежей с emoji до одного сообщения с правильным количеством и ссылкой. Анонимное чтение полного списка остаётся 401.
- Проверены отсутствие отправки неизвестному получателю при рабочем учёте, позднее подключение, фиксация пустого дня, отсутствие повторов после нового worker/подключения к базе, немедленная видимость новых и изменённых подписок в API без второй подборки в тот же день. После неподтверждённой попытки сохранённый текст остаётся прежним даже после редактирования подписки.
