# 07: Доставка напоминаний при сбоях

**What to build:** Владелец получает актуальное напоминание после временного сбоя без накопления старых сообщений; обычные параллельные исполнители не создают дубли, а постоянная проблема с ботом видна в приложении. Дополнить работающую ежедневную подборку правилами надёжности из спецификации.

**Blocked by:** 06 — Ежедневная подборка платежей.

**Status:** ready-for-agent

**User stories:** 26, 27, 28, 29, 30, 32.

- [x] Временные сетевые ошибки и ограничения частоты вызывают повтор с задержкой с учётом ответа Telegram. Содержимое подборки остаётся зафиксированным; срок следующей попытки сохраняется после перезапуска.
- [x] При неопределённом результате отправка повторяется. Редкий дубль между принятием Telegram и фиксацией успеха допустим и описан; документированного ключа идемпотентности у sendMessage не предполагается.
- [x] После простоя в пределах дня подборка доставляется не раньше 10:00 и до конца дня по Москве. После полуночи старые задания и их повторы не отправляются; новая подборка рассчитывается для новой даты после 10:00.
- [x] После долгого простоя прогноз актуализируется общим правилом расписания, без рассылки подборок за прошедшие дни.
- [x] Атомарный захват и уникальность бизнес-даты предотвращают обычную одновременную отправку двумя исполнителями. После аварии захват можно восстановить; восстановление не создаёт бесконечно зависшую задачу.
- [x] Постоянный отказ, например блокировка бота, фиксируется как проблема доступности и не создаёт бесконечных частых повторов. Повторный `/start` проверяет восстановление подключения.
- [x] Ошибка доставки отражается в состоянии подключения в API и русском интерфейсе, при этом управление подписками продолжает работать.
- [x] Детерминированные проверки с PostgreSQL, управляемым временем и Telegram покрывают временную ошибку, ограничение частоты, таймаут с неизвестным результатом, перезапуск, восстановление захвата, двух исполнителей, 14:00, полночь и многодневный простой.
- [x] Браузерная проверка подтверждает видимую проблему бота и восстановление состояния. Записаны результаты проверок и завершение задачи.


## Implementation

**Состояние реализации: завершена.** Проверено 16 октября 2026 года. `ready-for-agent` сохранён как triage-метка. Зависимость 06 завершена до начала работы. Независимое двухосевое ревью выполняется после коммита; результат будет записан в `docs/reviews/07-resilient-reminders.md`.

Миграция 4 сохраняет число завершённых зафиксированных попыток (включая успех), срок следующего повтора и безопасную категорию последнего результата без ответов Telegram и секретов. Временные сетевые ошибки, таймаут с неизвестным результатом, HTTP 429 и временные ошибки сервера повторяются с задержкой 1–60 минут с увеличением после ошибок; более длинный `retry_after` Telegram соблюдается. Текст остаётся прежним после изменения подписок и перезапуска.

Атомарный захват `FOR UPDATE SKIP LOCKED` удерживается через внешнюю отправку и фиксацию результата. Второй исполнитель пропускает занятую подборку. При завершении процесса или потере соединения транзакция откатывается, освобождая захват без зависшей аренды. Подтверждённый успех и пустая подборка не повторяются. Окно между принятием сообщения и commit допускает согласованный редкий дубль; ключ идемпотентности Telegram не предполагается.

Отправка ограничена текущим московским днём начиная с 10:00; контекст внешнего запроса ограничен 35 секундами и полуночью. Старые задания и сроки повторов остаются журналом, но после перехода даты не отправляются. При длительном простое используется общий прогноз фиксированных периодов для текущей даты без рассылки за прошлые дни.

Постоянный отказ сохраняет ошибку подключения и блокирует новые отправки до успешной проверки `/start`. Существующие API и русский интерфейс показывают «Бот недоступен»; создание и изменение подписок доступны. Миграция Telegram 2 добавляет ревизию подключения, чтобы поздняя ошибка старой отправки не перезаписала более новую проверку `/start`.

Устройство и ограничения: [docs/daily-digest.md](../../../docs/daily-digest.md). Живая проверка с настоящим ботом и доменом остаётся частью настройки развёртывания задачи 09.
