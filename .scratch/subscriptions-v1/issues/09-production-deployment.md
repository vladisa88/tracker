# 09: Развёртывание первой версии на сервере

**What to build:** Владелец открывает первую версию по своему HTTPS-адресу, входит через настоящий Telegram, ведёт подписки и получает сообщения бота. Проверить совместную работу согласованных функций и эксплуатацию на собственном сервере согласно спецификации.

**Blocked by:** 03 — Редактирование, архив и восстановление; 04 — Прогноз расходов по валютам; 07 — Доставка напоминаний при сбоях; 08 — Резервное копирование и восстановление.

**Status:** ready-for-agent

**User stories:** 1, 2, 3, 5, 8, 11, 15, 16, 17, 18, 19, 20, 21, 22, 23, 31, 32, 33, 34, 35.

- [ ] Проверены окружение сервера, домен, существующий HTTPS-прокси и доступный способ развёртывания. Получены конфигурация Telegram Login/бота, числовой ID владельца и реквизиты внешнего хранилища; реальные секреты не записаны в репозиторий.
- [ ] Production Docker Compose запускает API, фоновый процесс и PostgreSQL с постоянным хранением. Собранный React и API доступны с одного origin по HTTPS; отсутствуют production-обходы входа и тестовые Telegram-адаптеры.
- [ ] Миграции применяются в описанном порядке; несовместимая схема и недоступная база отражаются готовностью. Перезапуск сохраняет подписки, сессии согласно их сроку, подключение и журнал доставки.
- [ ] Настроены разрешённые origin/callback Telegram Login. Настоящий владелец входит и выходит, чужой аккаунт не получает доступ; проверено подключение `/start` и реальное проверочное сообщение.
- [ ] Сквозной сценарий на телефоне и компьютере проходит создание, перезагрузку, редактирование, архивирование и восстановление. Итоги обновляются после каждого применимого действия; архив исключён из обоих показателей и напоминаний.
- [ ] Проверены светлый русский интерфейс, карточки/список, подписанные поля, клавиатура, reduced motion, состояния загрузки/ошибок и сохранение ввода. Нет фиктивной аналитики или действующих элементов будущих функций.
- [ ] Подтверждён реальный путь ежедневной доставки по Москве; управляемые тесты продолжают покрывать время и сбои без ожидания календарных дней. Обычный перезапуск не повторяет подтверждённую подборку.
- [ ] В production-настройках копия уходит во внешнее хранилище, видны результат и время последнего копирования. Восстановление проверено в отдельной базе; процедура не уничтожает рабочие данные.
- [ ] Документированы запуск, конфигурация, миграции, проверки готовности, перезапуск, копирование и восстановление, включая особенности журнала доставки после старой копии.
- [ ] Пройдены итоговые проверки API с PostgreSQL, фонового процесса, браузерных сценариев и восстановления. Записаны команды и результаты, реальные ограничения и завершение задачи. При отсутствии внешнего доступа/реквизитов завершённую подготовку и проверенный запуск отделяют от ещё не выполненного реального развёртывания; задача целиком не отмечается завершённой до выполнения требований.
