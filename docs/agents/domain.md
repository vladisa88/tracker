# Domain documentation

This project has a single domain context.

Before exploring an area:
- Read the root `CONTEXT.md`.
- Read relevant decisions in `docs/adr/`.
- Proceed silently if a domain document is absent.

Use the glossary's canonical terms in code, tickets and docs.
Surface conflicts with ADRs before changing their decisions.

For first-version implementation, read:
- `docs/requirements.md` — agreed product scope.
- `docs/design.md` — agreed architecture and interface.
- `docs/telegram.md` — integration facts and delivery limitations.

Keep `CONTEXT.md` a glossary. Record requirements and
implementation details in their respective documents.
