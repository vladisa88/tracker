# Устройство приложения

Продуктовые и технические решения первой версии подтверждены владельцем 16 октября 2026 года. Этот документ описывает реализацию; продуктовые требования находятся в [requirements.md](requirements.md).

## Приложение

Владелец выбрал отдельный фронтенд на JavaScript и бэкенд на Go. Фронтенд — React с Vite: адаптивный русский интерфейс, взаимодействующий с Go через HTTP API. PostgreSQL хранит данные; отдельный процесс того же Go-приложения выполняет отправку напоминаний.

Референсы: [React: создание приложения с собственным стеком](https://react.dev/learn/build-a-react-app-from-scratch), [Go net/http](https://pkg.go.dev/net/http).

Разделы кода: подписки и расчёт расписания, Telegram и доступ владельца, доставка напоминаний. Расчёты дат и сумм отделяются от обработки страниц и отправки сообщений, чтобы последующие функции можно было добавлять без переписывания правил подписок.

Docker Compose запускает Go API, процесс напоминаний и PostgreSQL; собранный JavaScript-фронтенд и API доступны через один origin. HTTPS настраивается с учётом существующего окружения сервера. Ежедневное резервное копирование выгружает базу во внешнее хранилище.

## Данные

Подписка: название, положительная сумма, исходная валюта, период в днях, следующая дата платежа и признак архива. Денежные значения хранятся точно, без двоичной арифметики с плавающей точкой. Даты платежей являются календарными датами по Москве.

Авторизация сопоставляет проверенную Telegram-идентичность с заранее заданным идентификатором владельца. Получатель уведомлений и состояние подключения бота хранятся отдельно от подписок.

## Интерфейс

Светлый интерфейс: молочный фон, графитовый текст, зелёные акценты, крупные суммы и цветные значки подписок. На телефоне подписки отображаются карточками, на компьютере компактным списком. Добавление и редактирование сопровождаются аккуратными анимациями.

## Напоминания

Согласован отдельный шаг подключения через `/start` с проверочным сообщением. Планировщик и журнал отправок предотвращают обычные повторные рассылки. При неоднозначном сетевом сбое отправка повторяется; владелец согласился с возможностью редкого дубля. Факты и ограничения Telegram приведены в [telegram.md](telegram.md).

После успешной ежедневной подборки новые и изменённые подписки учитываются в следующей отправке; дополнительное сообщение в тот же день не создаётся. Проверочное сообщение подключения бота является отдельным действием.

## Данные перед развёртыванием

Потребуются точный домен, окружение и способ доступа к серверу, конфигурация Telegram-приложения/бота, числовой Telegram ID владельца и место хранения копий. Секреты не записываются в документацию и репозиторий.
