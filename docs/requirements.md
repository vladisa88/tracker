# Первая версия

Требования первой версии подтверждены владельцем 16 октября 2026 года. Изменения объёма первой версии согласуются отдельно.

## Согласовано

- Приложение предназначено для одного владельца, доступно через интернет и требует авторизации.
- В интерфейсе отображается список подписок с суммой, валютой и следующей датой платежа; можно добавлять подписки.
- Подписка описывает регулярный расход с заранее известной суммой: сервис, аренду, интернет или другое обязательство.
- Поля подписки: название, сумма, валюта, следующая дата платежа, периодичность.
- Периоды подписок: 30, 90, 180 и 365 дней. Ранее согласованное правило календарных месяцев заменено фиксированными интервалами в днях; даты могут сдвигаться относительно календарного месяца.
- Приложение прогнозирует расходы. Даты переходят автоматически, подтверждение оплаты и история фактических списаний в первую версию не входят.
- Telegram: одно сообщение в день в 10:00 по Москве с платежами через три дня и сегодня. При отсутствии таких платежей сообщение не отправляется.
- Валюта хранится у каждой подписки. Итоги отображаются отдельно по валютам, без конвертации по курсу.
- Приложение предполагает дальнейшее расширение; состав следующих версий пока не определён.
- Подписки можно редактировать, архивировать и восстанавливать. Архивные записи находятся в отдельном списке и исключаются из будущих расходов и напоминаний. Срок оставшегося доступа к сервису не учитывается.
- Вход через Telegram; доступ разрешён только аккаунту владельца. Подключение бота — отдельный шаг с проверочным сообщением.
- Если отправка в 10:00 пропущена, напоминание доставляется до конца того же дня по Москве. На следующий день отправляется актуальная подборка без накопления старых напоминаний. При временной ошибке Telegram отправка повторяется.
- Над списком: платежи в ближайшие 30 дней и «В среднем за 30 дней», отдельно по валютам. Для средней нагрузки стоимость каждой активной подписки умножается на 30 и делится на период в днях. Список отсортирован по ближайшей дате платежа.
- Интерфейс на русском, ориентирован на телефон и адаптирован для компьютера. На основном экране — ближайшие платежи, итоги и кнопка добавления подписки.
- Для размещения есть собственный сервер. Согласована общая форма: одно небольшое приложение с базой данных и резервным копированием на одном сервере.
- При добавлении следующая дата платежа должна быть сегодня или в будущем. При восстановлении из архива пользователь заново указывает следующую дату.
- У действующих подписок прошедшие даты автоматически переносятся на целое число периодов с сохранением исходного графика.
- Развёртывание через Docker Compose на отдельном домене или поддомене с HTTPS. Пользователь подтвердил наличие домена; точный адрес и окружение сервера ещё не проверены.
- Ежедневная резервная копия базы, хранение последних семи копий вне сервера; допустима потеря последних суток изменений. Пользователь подтвердил наличие внешнего места хранения; конкретное место ещё не указано.
- Фронтенд на JavaScript с тщательно проработанным интерфейсом; бэкенд на Go. Предложение Python/Django отклонено.
- Согласованный стек: React + Vite, Go, PostgreSQL. Детали устройства описаны в [design.md](design.md).
- Светлый интерфейс: молочный фон, графитовый текст, зелёные акценты, крупные суммы и цветные значки подписок. На телефоне — карточки, на компьютере — компактный список. Аккуратные анимации добавления и редактирования.
- Бот подключается отдельным шагом через `/start` с проверочным сообщением.
- При неоднозначном сетевом результате отправка повторяется; редкий дубль в таком случае допустим. Успешные отправки записываются, чтобы предотвращать обычные повторы.
- Изменения после успешной ежедневной подборки учитываются в следующей отправке без дополнительного сообщения в тот же день.

## Перед реализацией и развёртыванием

- Требования Telegram проверены и описаны в [telegram.md](telegram.md).
- Продуктовые и технические вопросы интервью закрыты; итоговое общее понимание подтверждено. Следующий этап — спецификация реализации и самостоятельные задачи с зависимостями.
- Точный адрес приложения, окружение сервера и место резервных копий потребуются перед развёртыванием.
