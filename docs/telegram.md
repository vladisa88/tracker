# Интеграция с Telegram

Факты проверены по официальной документации 16 октября 2026 года. Сценарий подключения и компромисс повторной доставки согласованы в интервью.

## Вход

Актуальный [Telegram Login](https://core.telegram.org/bots/telegram-login) поддерживает OIDC Authorization Code Flow с PKCE. Для сайта регистрируются разрешённые origin и callback URL через BotFather. Сервер должен проверять полученные токены и отдельно ограничивать доступ числовым Telegram ID владельца. Старый iframe widget помечен как legacy.

## Подключение бота

Согласован отдельный шаг: владелец открывает бота и отправляет `/start`; приложение проверяет ID отправителя и личный тип чата, сохраняет `chat_id`, отправляет проверочное сообщение. Обновления можно получать через long polling без отдельного публичного webhook.

Это выбранный сценарий, а не единственный способ получить право писать пользователю: новый Login также предоставляет [scope telegram:bot_access](https://core.telegram.org/bots/telegram-login#available-scopes). В первой версии используется отдельный `/start` для явного подключения напоминаний.

Источники: [Message](https://core.telegram.org/bots/api#message), [getUpdates](https://core.telegram.org/bots/api#getupdates), [sendMessage](https://core.telegram.org/bots/api#sendmessage).

## Надёжность отправки

У [sendMessage](https://core.telegram.org/bots/api#sendmessage) нет документированного ключа идемпотентности. Журнал отправок и запрет параллельной обработки одной подборки предотвращают обычные повторы, но после сетевого таймаута неизвестно, принял ли Telegram сообщение. Повторная попытка в таком случае может создать дубль. Согласовано: повторять отправку ради доставки напоминания, принимая редкий дубль при неоднозначном результате.
